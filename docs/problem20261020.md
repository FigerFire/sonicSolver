# 自由方程耦合：当前状态与剩余任务

更新：2026-10-22。本文根据当前源码及 A1/A2/A3/A4、核心单路径收口报告重写原六项问题，避免把已退役的实现继续列为待办。本次是文档整理，不是新能力完成声明，也没有重新执行 CFD 验证。

## 1. 已完成的基础，不再重复建设

**Math 定义数学，WHAT 组织方程，Numerics 实现算法，WHICH 选择实现；STATE 声明状态，HOW 决定求解过程。** Math 是公共基础库，不是第五个 authority。

| 能力 | 当前状态与边界 |
|---|---|
| 数学签名 | 七维量纲指数、张量阶数、指标尺寸/结构；未声明与无量纲区分 |
| Typed WHAT | 同一 FormulaExpr 在构造时调用 Math 传播签名；Equation 检查两侧兼容；重建继续经过规则 |
| 基础符号运算 | 加减、标量乘除、收缩及梯度/散度等已有规则；扩展算子可声明自己的签名规则 |

| 模块数学归属 | core/system/SF_domainMathematics.h 已删除，声明归还实际模块 |

### “自动校验代数”的准确含义

Math 自动校验的是**已声明表达式的数学类型**：量纲、阶数、分量/收缩兼容以及算子签名。它不是通用代数证明器，不自动证明方程正确、闭合、独立、可解、稳定、守恒或收敛，也不自动生成 Jacobian。

普通 double/Vector3 数值运算没有附带物理量纲时，不能获得相同的量纲检查；带签名的 Expr 才经过该规则。除零、非有限值、奇异矩阵等动态问题仍由具体数值实现检查。

签名只保存在符号和表达式元数据，不放进每个 cell。未知符号先解析再构造 Typed WHAT；逻辑符号允许没有物理数组，但被执行消费时必须有实际实现/绑定。

基础规则包括：加减类型兼容、标量乘除量纲指数加减、grad 升阶且除以 L、div 合法收缩后降阶且除以 L、laplacian 保阶且除以 L²、ddt 保阶且除以 T。指定空间方向偏导与任意坐标偏导能力须按具体实现区分。连续 div 与投影/积分面通量 balance 不混用签名。

## 2. 自由耦合现在真正困难在哪里

### 问题一：数学合法与数值能力覆盖仍有距离

WHAT 能表达，不表示当前选中的 provider 可以实现。

A6 已实际完成：纯局部反应、同一目标多个常系数扩散、不同 Stage unknown 的交叉扩散、三分量向量扩散/线性反应。每个 occurrence 独立绑定系数、输入及 Central2 实现；没有假扩散或 target 替换。普通路径支持 signed 常系数，不替用户修改不稳定的选择。保留原 transport/shared/SST 能力与数学。

独立解析/半离散参考、Euler/RK4 时间收敛、向量空间二阶收敛及六个 native IO 算例已验证。空间上局部的方程不强制边界/halo；当前 native mesh reader 的 NG>0/非退化几何约束仍单列。STATE/数学/输出分别保留三分量，不将向量硬绑为 U。

**仍待办**：变系数或非线性 diffusion、各向异性、一般张量/收缩数值执行、曲线网格、MPI/new multipatch、一般隐式与任意 source port。数学合法不等于已有这些实现。不补虚假项、不自动换方法。见 [A6 数值与资源报告](explicit-a6.md)。

### 问题二：公共编译流程仍承担具体后端 lowering 条件

该问题已在 A5 选定范围收口：公共 NumericalCompiler 调用所选 provider 的 lowerSpatial，融合符号/系数/位置要求归 SF_fusedSpatial。A6 继续使用这一边界，公共 compiler 和 PlanExecutor 未增加 reaction/cross/vector 判断。

专用 kernel 保留自身真实能力限制。WHICH 选择失败不另找替代方法；符号合法、实现支持和资源实际可绑定仍是三个不同确认点。

### 问题三：时间项、隐式系统与约束不能靠代数搬项解决

现有 explicitFormulaRhs 只提取受支持的正号 additive ddt(target)，不自动处理：

- `a*ddt(c)` 的质量系数或质量矩阵求逆。
- `ddt(rho*c)` 到另一个主变量的转换。
- 多个未知量的隐式联立、非线性 residual/Jacobian。
- 一般 DAE、积分约束、乘子及 nullspace/gauge。

**待办**：为具体求解方法定义实际 residual、mass、linearization 或 block 能力，再由对应方法解释 WHAT。暂不建设万能符号求解器。方程数与未知量数相同也不是可解性证明；只能做有依据的引用/结构检查和后端所需的闭合条件验证。

语义改写必须保留 provenance、occurrence、守恒形式和实际运算含义，不任意重排浮点累加，不自动线性化。

### 问题四：耦合方式必须有执行语义，不能只连接变量名

当前已有顺序、Loop、同步显式 Stage，以及受支持压力流程。A4 不等于通用 monolithic、Newton 或 Subcycle。

真正的组合还要明确：

- 显式方程是否读取同一个 stage 的所有状态。
- 顺序求解是否使用前一方程刚更新的值。
- 系数何时刷新、Frozen/Lagged 在哪层生效。
- 非线性迭代的终止、失败及物理 Commit 条件。
- 子循环如何获得边界/其他场时间值，反馈如何汇总。

**待办**：按实际算法分别补 HOW 高层语义和所选方法的 lowering。数学耦合环可以合法，派生依赖环或未发布读取不能混为一谈。Subcycle 仍明确拒绝；不能只运行 N 次原循环就宣称完成。

复杂子循环、非线性算法的时间插值、反馈与收敛选择需要用户明确时，应先问具体问题，不替用户决定数学。

### 问题五：数学需求还不能全面驱动资源组合——A5 主任务

STATE producer 已统一，但这是视图绑定能力，不是任意资源的自动生成能力。

SF_execution.cpp 仍按 flow.eulerian-pressure、flow.conservative/pressure-operators、scalar provider 选择具体装配入口。原热物性 producer 仍借用 Field cache，不能当成任意独立输入的通用热力学函数。Surface/Face/phase/MPI/边界资源也需要实际实现。

**待办**：从已编译需求组合真实资源，明确 allocator/binder、owner、layout、初值/边界、版本与 publication。先证明一个受支持的真实组合能运行，再迁移并删除被替代入口。没有新的 solver family、第二份 Q/clock、全局资源大管家或新旧双路径。

验收应覆盖实际分配/句柄、共享与冲突、缺资源诊断、数据就绪和运行结果；只看注册表里多了字段不算完成。

### 问题六：解释、入口与验证需要真实覆盖，而非数学注册即成功

当前已有数学到 compiled consumer/Plan 的覆盖和文本 Explain。仍需区分：数学可声明、编译可绑定、运行资源可满足、数值已验收。

- 合法但不支持的数学应保留准确阻断链，不生成假计划。
- CLI 外层仍存在 CONFIGURATION INVALID 标题；不要让它掩盖内部 Unsupported 的实际原因。
- 结构化 Explanation 可复用现有查询逐步形成，不复制数学或建立展示 registry。
- 内部 replace/disable 与 native 输入开放范围不同；外部语言继续后置。
- 新的内部数学/数值实现不应要求修改中央名称表或执行器。

**待办**：先完善真实编译事实的统一解释，再让 GUI/预制/外部输入消费同一结果。外部公式只生成现有贡献；未知离散实现不能因输入语言更自由就自动获得。

## 3. 下一阶段工作顺序

### P0：先明确当前数值基线的已知异常

核心单路径报告明确保留：serial/MPI pressure shape 阈值超限、Level-set 历史 isolated-kernel 参考失配及 MPI 正确性问题、canonical KKT 输入冲突后的 production 未执行、surface IBM 完整时域/力矩/功率等未覆盖。

这些不都是本轮回归，也不能被文档概括成“全部通过”。先分类定位影响下一轮的基线；不要求先实现所有物理能力，但不能通过删测试、放宽容差或替换参考消除证据。

### P1：编译与后端职责精简

A5 已将融合后端专用 lowering 收敛到所选具体实现；A6 保持这一边界。共享结构查询只维护一处，不恢复兼容入口；现役流体/标量保护继续执行。

### P2：A5 资源组合闭环

以实际可运行的有限组合为起点。冻结需求→真实绑定→完整执行→Explain 一致。迁移消费者并同轮删除旧装配路径，不能只加一个新 binder 后旧分支永远不退役。

### P3：按需求扩大数值与 HOW 能力

A6 已闭合纯反应、多/交叉常系数扩散和三分量向量的选定显式能力。后续变系数、隐式块、Subcycle 分别立项，先明确数学与独立参考，再实现 provider 和执行语义；不承诺全部自由公式求解。

### P4：结构化解释与外部入口

已有 Explain 持续保护；后续形成必要的结构化输出，再扩大预制/GUI/外部公式。通用 Jacobian、变分前端、动态插件并非本阶段默认任务。

## 4. 文件组织与删除规则

- Math 使用 namespace、值类型和普通函数；无 Field/Mesh/MPI 依赖。
- Numerics 无状态 kernel 用函数；持矩阵、预条件器或 workspace 生命周期的实现可用类。
- WHAT/STATE/HOW/WHICH 使用可解释的强类型声明，不为编译方便制造晦涩的另一套语言。
- 压力耦合方法属于 solver 方法；控制层选择和展开贡献，不持有另一套循环。
- 短名、少文件，复用真实职责；不按超过500行机械拆分。
- 允许破坏旧内部 API；调用者直接迁移，旧接口、转发和重复实现同轮删除。
- SystemContribution→Contribution 是集中命名清理，不作为数学能力完成的指标；实际改名前核对消费者，不保留长期别名。
- 已删 authored/legacySource、StateDerivation、domainMathematics、Legacy FormulaCall 不再列作待办。
- capability 检查和有效数值 kernel 不因“旧”而删除；精简不等于放宽正确性条件。
- 算例为主要执行验证，保留少量不可替代的类型、版本、资源与独立数学测试；只服务退役 API 的测试随之删除。

## 5. 最终冻结标准

对明确声明签名、符号、状态与求解需求的新方程：

1. 数学非法时，在 Math/WHAT 边界准确拒绝。
2. 数学合法但缺方法/资源时，保留可追溯的 Unsupported 说明。
3. 已有对应实现时，沿统一编译、资源和执行链求解，不修改中央模型判断。
4. 所有实际方程/项、版本、方法、资源、循环和提交均可解释。
5. 新方法可以增加专用 kernel，但不新增平行 authority 或全局生命周期。

冻结的是共同语义与扩展入口，不是所有数学能力已经存在。Math 签名基础已经成立，下一步主要工作在 numerical capability、HOW 与 resource composition。
