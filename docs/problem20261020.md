## 4. 主要源码障碍

### P0：固定模型匹配仍掌握普通数学入口

`src/solver/system/SF_builtinProviders.cpp` 中 TurbulenceTransport 要求 k 与 omega/epsilon 的固定配对、目标与 equation 同名、特定 provider-owned 存储及 mu_t closure；supportedRasMathematics 重建整式并做 canonical 比较。其 frozen kernel 仅实现声明的 source/diffusion，不包含对流。

### P0：系数计算和资源准备混合

### P1：普通标量输运的剩余数值边界

普通标量编译现集中在 `SF_scalarMethod.cpp`，SST 闭合由 `SF_sstMethod.cpp` 处理。容量形式仍要求已支持的载体与实际共享质量通量。节点和度量输运的离散、边界闭合和所需资源各有实现。固定时间体积输运使用已发布的校正通量及本区间入口快照。扩展其他载体、几何或版本组合需要相应的 kernel 与绑定。

### P1：数值能力与接口能力仍有缺口

普通方法仍受场形状、版本、OldTime 快照、源回调、单 patch/串行边界等限制；线性块不是一般非线性隐式求解。每条限制需归类为数学输入条件、过程条件或真实实现缺口。
